# CarRadar — архитектура

## Стек
Python 3.12 · FastAPI · aiogram 3 · SQLAlchemy 2 (async) + asyncpg · Alembic · httpx · PostgreSQL 16 · Redis 7 (rate-limit/кэш) · React + TS + Vite + Telegram WebApp SDK · Docker Compose.
Celery/ARQ **не используются**: источник правды — PostgreSQL (таблицы `search_queries`, `notifications` = очередь/outbox), а мониторинг — один asyncio-процесс. Это проще и переживает перезапуск.

## Процессы (один образ, разные команды)
| сервис | что делает |
|---|---|
| `api` | FastAPI: REST для Mini App, проверка `initData`, раздача собранного miniapp |
| `bot` | aiogram: /start, /filters, /favorites, /settings, /help, inline-кнопки уведомлений |
| `monitor` | цикл опроса источников + рассылка уведомлений + проверка активности объявлений |
| `db`, `redis` | хранилища |

## Быстрое обнаружение без запроса «на пользователя»
1. Фильтр пользователя → `compile()` → **грубый запрос для источника** (марка/модель/цена/год/топливо… то, что умеет сам сайт) → канонический JSON → `sha256` = `query_hash`.
2. Одинаковые запросы разных пользователей = **одна строка `search_queries`** (связь `filter_queries`). Опрашивается один раз.
3. Планировщик: `SELECT … WHERE next_poll_at <= now()` → для каждого источника свой семафор и лимитер частоты. Запрос идёт с сортировкой «новые первыми», берётся **только первая страница (32 шт.)**.
4. Идём по результатам, пока не встретим `last_seen_id`/уже известный `external_id`. Новые → `INSERT … ON CONFLICT DO NOTHING` в `listings` (дубликатов нет, UNIQUE(source, external_id)).
5. Для каждого нового объявления: точное сопоставление с **всеми** фильтрами, привязанными к этому запросу (мелкие условия — исключённые слова, оснащение, продавец — проверяются локально) → `matches`.
6. Группируем по пользователю: **одно** уведомление на (user, listing) со списком сработавших фильтров (UNIQUE в `notifications`). Учитываются скрытые, ночной режим, дайджест, источники.
7. Отправка: воркер забирает `pending` из outbox с учётом лимитов Telegram (≈25 msg/s глобально, 1/s на чат), ретраи, `failed` после N попыток.
8. Страховка от пропусков: если вся первая страница оказалась новой — берётся следующая.

Честно про «реальное время»: это **опрос раз в `poll_interval_sec`** (по умолчанию 60 с, меняется админом в `app_settings` без рестарта). Задержка уведомления ≈ интервал + время запроса.

## Устойчивость
Таймауты httpx, экспоненциальные ретраи на 5xx/сетевых ошибках; 429 → уважаем `Retry-After`, пауза источника (`parser_status.paused_until`); 403 → состояние `blocked`, пауза, запись в `error_log`, **без попыток обхода**. Детект смены вёрстки: если JSON/ключи не разобрались → `schema_changed`, алерт админу. Состояние курсоров в БД → после рестарта продолжаем с места.

## Источники — результат исследования (05.11.2026)
- **OTOMOTO**: `robots.txt` разрешает `/osobowe/…` (запрещены `/api/`, `/ajax/`). Страница поиска (SSR Next.js) содержит `__NEXT_DATA__` → `urqlState → advertSearch.edges[].node` с id, `createdAt`, ценой, `parameters` (make, model, year, mileage, engine_capacity, engine_power, fuel_type, gearbox…), локацией, продавцом, превью. Это публичные данные страницы, один GET на запрос, без обхода защиты. Полные фото, VIN и описание — со страницы объявления (запрашивается только для **нового** объявления).
- **OLX Polska**: с машины разработки и `robots.txt`, и поиск отдают **403 от CloudFront**. Мы это не обходим. Варианты: (а) проверить с серверного IP при деплое; (б) официальный OLX Partner API (developer.olx.pl) — требует регистрации клиента, публичного поиска по чужим объявлениям он, как правило, не даёт; (в) если доступа нет — OLX помечается `blocked` в статусе, остальное работает. Парсер OLX пишется по интерфейсу `Parser` и включается, когда доступ подтверждён.

```

  shared/        конфиг, FilterSpec, i18n
  db/            модели, сессия
  parsers/       base.py, otomoto.py, olx.py, нормализация
  monitoring/    планировщик, компиляция фильтра, matcher
  notifications/ outbox-воркер, форматирование
  bot/           aiogram handlers
  api/           FastAPI, auth (initData HMAC), роуты
backend/migrations/  alembic
miniapp/             React + Vite
```

## Безопасность
`initData` проверяется HMAC-SHA256 с ключом от токена бота + `auth_date` не старше 24ч; Telegram ID берётся только из проверенных данных. Админ — по `ADMIN_IDS`. Pydantic-валидация, ORM-параметры (нет SQL-инъекций), rate-limit на Redis. Секреты — только `.env` (в `.gitignore`).
